# 001. Сначала токен, затем слот

Токен списывается до попытки занять слот и не возвращается. Так очередь не заполняется запросами, которые уже превысили частоту, а повторная попытка после `503` тоже учитывается в квоте. Следствие — клиент может исчерпать токены, даже если backend обработал меньше запросов.

Очередь хранит только ожидающих. При отмене узел удаляется под тем же lock, которым защищена передача слота. Если слот уже передан, но ожидание завершилось отменой, ожидающий возвращает слот следующему запросу. Владелец держит слот до окончания обращения к backend и буферизации ответа. Отправка готового ответа клиенту проходит после освобождения слота.
